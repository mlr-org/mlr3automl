# mlr3automl (development version)

* feat: The auto learners gained the `bagging` and `bagging_folds` parameters that train each configuration as a bagged ensemble in the style of AutoGluon and TabArena. A configuration trains `bagging_folds` child models on a cross-validation of the training data, the test prediction is the equally weighted average of the children, and the configuration is scored by its out-of-fold predictions. The neural network learners (mlp, resnet, and ft_transformer), fastai, and tabpfn instead fit a single final model on the complete training data after the cross-validation. The final model reuses the exact model of the winning configuration trained during tuning. The new `PipeOpLearnerBagged` implements the bagging.
* feat: The auto learners gained the `bagging_small_folds`, `bagging_small_repeats`, and `bagging_small_size` parameters. Tasks with fewer than `bagging_small_size` rows (default 500) are bagged with a `bagging_small_repeats` times repeated `bagging_small_folds`-fold cross-validation, so a configuration trains 25 child models by default instead of 8. This follows AutoGluon, which repeats the cross-validation on small data sets to reduce the variance of the out-of-fold score. The new `bagging.repeats` parameter of `PipeOpLearnerBagged` implements the repetitions.
* BREAKING CHANGE: `bagging` is enabled by default. The tuning archive now reports the scores in the `internal_valid_score` column instead of the measure column, the tuning resampling is `insample`, and the `resampling` and `small_data_resampling` parameters have no effect. Set `bagging = FALSE` to restore the previous behavior.
* fix: The lightgbm and catboost branches now include a `fixfactors` step, so the factor levels created by the character conversion stay consistent between training and prediction. Previously, prediction could fail on small data splits when the observed levels differed from training.
* fix: The default configuration of the tabpfn learner in the initial design now matches TabPFN-3. The number of estimators changed from 4 to 8 and the softmax temperature from 1.0 to 0.9, which were the defaults of TabPFN-2.
* fix: The tabpfn learner now sets `auto_scale_n_estimators = FALSE`. TabPFN-3 otherwise raises the number of estimators on its own when the task has more features than a single ensemble member sees, which overrides the tuned value. This requires `mlr3extralearners` 1.6.0.9000 or later, which is now the minimum version.
* fix: Tuning on subspaces no longer fails when a learner has internally tuned parameters, e.g. `xgboost.nrounds` or `ft_transformer.epochs`. The subspaces are now derived from the search space of the tuning instance, which no longer holds the internally tuned parameters.
* fix: The torch learners (mlp, resnet, and ft_transformer) now train on the CPU when `devices` does not include `"cuda"`. Previously they passed `device = "auto"` to `mlr3torch`, which selects the GPU whenever one is available, so they ignored `devices = "cpu"` and the resource accounting of the workers.
* fix: The torch learners (mlp, resnet, and ft_transformer) now train with a batch size of 256 instead of 32 on the GPU. A batch of 32 rows leaves the GPU mostly idle because kernel launches and host to device transfers dominate the step time.
* fix: The torch learners (mlp, resnet, and ft_transformer) are no longer removed from the search space by `memory_limit` when they train on the GPU. Their memory estimates are fitted on host memory measurements, which do not describe the memory the model allocates on the GPU.
* fix: The gpu compute profile is now exempt from the large data set rules. Its number of workers is fixed by the number of GPUs, so reducing it does not free any resources, and its worker previously received the CPU cores and the memory that are freed on the cpu profiles.
* fix: The number of workers of a compute profile is now reduced to a quarter rounded up instead of rounded down, so a profile no longer loses more than the intended factor, e.g. 7 workers are reduced to 2 instead of 1.
* feat: New learner id `"tabfm"` adds the TabFM tabular foundation model from `mlr3extralearners` to the search space, along with the new auto learners `classif.auto_tabfm` and `regr.auto_tabfm`. It runs via `reticulate` and is registered for `"cuda"` only, because it predicts in context and runs the backbone over the training rows once per estimator, which is too slow to be useful on the CPU. Construct `AutoTabFM$new(devices = c("cpu", "cuda"))` and re-register it in `mlr_auto` to run it on the CPU anyway.
* feat: The auto learners gained the `n_cpu` and `n_gpu` parameters that override the per-learner resource requirements. When the requirements are mixed, `"cuda"` is part of `devices`, and the workers are distributed over the `mirai` compute profiles `"mlr3automl_cpu"` and `"mlr3automl_gpu"` with `rush::rush_plan(profiles = c(mlr3automl_cpu = 7, mlr3automl_gpu = 1))`, the gpu learners run on the gpu profile and the cpu learners on the cpu profile. The workers of a profile only evaluate points of the learners of that profile.
* BREAKING CHANGE: The auto learners are now tuned with `mlr3mbo::TunerADBOThompson` instead of `mlr3mbo::TunerAsyncMbo`. Every learner is a subspace of the search space, each worker samples the learner to work on via Thompson sampling over the learners of its `mirai` compute profile, and the surrogate model of a worker is fitted on the evaluations of the sampled learner only. The tuner requires the `"mirai"` worker type and either no compute profiles, a single compute profile, or the profiles `"mlr3automl_cpu"` and `"mlr3automl_gpu"`. The tuning archive gains the `.subspace` column that holds the learner id of every evaluation.
* BREAKING CHANGE: With `devices = c("cpu", "cuda")`, the boosting learners (xgboost, lightgbm, and catboost) now train on the CPU by default because their default `n_gpu` requirement is 0. Set e.g. `n_gpu = c(xgboost = 1)` to train them on the GPU again.

* Initial CRAN release.
